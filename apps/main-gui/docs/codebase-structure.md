# Codebase structure

The source is organized vertically, the way
[TkDodo describes it](https://tkdodo.eu/blog/the-vertical-codebase): folders are
named for what the code _does_, not for what it technically _is_. There is no
`components/`, `hooks/`, `utils/` or `types/` directory. Everything a slice of
the product needs — markup, styling, images, and later its hooks, queries and
types — sits in one folder, because code that changes together should live
together.

`apps/main-api` is already arranged this way (`organizations/`, `tallies/`,
`users/`), and this app follows the same file naming: kebab-case, with an
`index.ts` barrel per vertical so other verticals import from the folder rather
than reaching into its files.

```
src/
  main.tsx              entry: theme provider, baseline, router
  routeTree.gen.ts      generated by @tanstack/router-plugin — do not edit
  routes/               one file per URL, each a thin adapter over a vertical
  design-system/        the MUI theme: palette, type, component defaults
  site-chrome/          the shell every route renders inside: header, nav
  landing/              the marketing landing page
  coming-soon/          the placeholder the unbuilt routes render
```

## The rules

**`design-system/` is the only thing everyone may depend on.** It exports one
MUI theme and nothing else. The palette, the type scale, the gutters, the
gradients, and the component defaults all live in `theme.ts`, and
`main.tsx` is the only place a `ThemeProvider` appears. Nothing in it knows
about the landing page.

**No component defines a colour, font or size of its own.** Styling goes through
MUI: `sx` for one-off layout, the theme for anything a second component would
want. A literal hex outside `design-system/theme.ts` is a bug — reach for
`palette.brand`, `palette.primary`, or `text.secondary` instead. There are no
`.css` files and no class names to collide, which is what keeps verticals from
leaking into each other.

**Routes stay thin.** A route file declares the route and renders one thing from
a vertical. Anything longer than that belongs in the vertical, not in
`src/routes`.

**Shared code becomes its own vertical.** `coming-soon/` exists because four
routes need it. When a second page needs something the landing page owns, it
moves out into a vertical of its own rather than being imported across.

## Adding a page

1. Add the vertical: `src/<name>/`, with `<name>.tsx` and an `index.ts` that
   exports the entry component.
2. Add `src/routes/<name>.tsx` rendering it.
3. The router plugin regenerates `routeTree.gen.ts`, and the header's `<Link>`
   to `/<name>` starts type-checking.

## Extending the theme

`theme.ts` augments MUI's `Palette` with a `brand` section for the things
Material has no slot for — the page's background gradient, the artwork's glow,
the button gradient, the nav text colour, the gutter width. Add to that object
and the module augmentation beneath it, and `theme.palette.brand.<x>` is typed
everywhere.
